# AP Refactor 参考

需要执行具体重构步骤时再读本文件。`SKILL.md` 管流程与约束；这里补充手法、气味和验证。

## 什么算重构 / 什么不算

**算：** 改变代码组织方式，调用后可观察结果与以前相同。

**不算（应停或改走 ap-task-executor）：**

- 新功能、新分支逻辑、新默认值
- 修复缺陷（除非该缺陷使当前行为无法表征；此时先停，问用户是否拆成 fix 任务）
- 性能优化（若改变算法复杂度或并发语义，属于行为/性能任务）
- 依赖升级、构建配置、CI 大改
- 仅为通过 lint 而改写无关模块

错误文案、日志内容、抛错类型、事件顺序、网络请求形状均视为可观察行为，默认保持。

## 常见气味 → 手法

| 气味          | 优先手法                       | 注意                                    |
| ------------- | ------------------------------ | --------------------------------------- |
| 过长函数/组件 | 抽取函数或子组件               | 先抽纯计算，再抽带副作用的片段          |
| 重复逻辑      | 抽取共用函数；重复结构考虑模板 | 不要过早抽象成「可能用到」的泛型        |
| 参数过多      | 用已有类型对象收拢；拆函数     | 不要发明新的公共配置模型                |
| 模块职责混杂  | 按职责拆文件                   | 保持原有导出路径或做兼容再导出          |
| 错误的位置    | 把函数移到它所属的包/层        | 遵守 ADR 的 apps/services/packages 边界 |
| 过深嵌套      | 提前返回、抽取条件             | 不要改条件含义                          |
| 神秘命名      | 重命名                         | 同步类型、测试、注释；分步改导出名      |
| 特征依恋      | 把逻辑移到数据所在模块         | 避免循环依赖                            |
| 过宽可见性    | 改为模块内私有                 | 先确认包外无引用                        |

一次只选一种主导气味处理。其余记入 Notes。

## 小步顺序（推荐）

在同一段代码上，按风险从低到高：

1. 重命名局部变量/函数（工具或精确替换）
2. 抽取纯函数
3. 抽取带依赖的函数，参数显式传入
4. 移动文件，在原路径再导出（若必须保持 import）
5. 删除再导出（确认无外部引用后）
6. 去重：先并列调用新函数，再删旧副本
7. 收紧导出与内部结构

不要跳到第 6、7 步却还没通过第 1–3 步的测试。

## 本仓库验证

按触及的包运行，避免无必要的全仓耗时；跨包再升级：

```bash
pnpm lint:fix
pnpm typecheck
```

若任务或包脚本提供更窄的 `typecheck` / 测试命令，优先用窄命令，并在 Completion 写明。

依赖：只允许 pnpm；共享版本用 catalog；`shamefully-hoist=false`，用到的依赖必须在该包 `package.json` 声明。重构默认不新增依赖。

## 公共契约清单

动手前扫一遍，列入不变量：

- 包的 `exports` / 已发布类型
- Desktop 与 Server 的 HTTP、AG-UI 协议
- IPC / preload 暴露
- 环境变量名与配置键
- 错误码、事件名、磁盘上的数据格式

只改内部组织时，上述表面保持不变。若任务要求移动导出：保留旧路径再导出，或在 Constraints 写明破坏性变更并得到用户确认。

## 表征测试要点

- 断言**现在实际发生的事**，不是「理想上应该怎样」
- 覆盖：主路径、边界输入、错误路径、导出符号是否仍存在
- UI：优先测纯逻辑与状态变换；避免用重构之机改视觉
- 测完再重构；重构后这批测试应仍然全绿且断言无需改语义（仅可随符号移动改 import）

## 何时升级为决策 / 停下来

停止并询问用户（需要时提出 ADR 草案，但不要写入 `.agents/ap-config/work-data/decisions/`）：

- 必须改变公共契约才能继续
- 要把代码迁到另一个物理层（app ↔ service ↔ package）
- 引入新的共享抽象，影响多个包
- 删除仍可能被外部使用的 API
- 发现现有实现与 ADR 冲突
- 护栏成本高于本次重构收益（范围过大）

## 完成前检查

- [ ] 每一步都是单一结构变换
- [ ] 不变量仍然成立
- [ ] 无新功能、无关 bugfix、无范围外文件
- [ ] 导出函数有用途/意图/原因注释
- [ ] lint / typecheck（及测试）已跑且通过
- [ ] TASK 已更新或已向用户说明未入任务队列的原因
- [ ] Notes 记录了刻意没做的气味与后续建议
