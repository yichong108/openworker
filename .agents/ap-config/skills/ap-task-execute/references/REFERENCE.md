# ap-task-execute 参考

同一时刻只实现一件 TASK；禁止并发；允许串行。只执行 Status 为 TODO 的任务。选取按优先级 P0 > P1 > P2 > P3，同级编号小的先做。下表「本轮是否继续」指当前条处理完后能否接着做下一件（仍按优先级重选）。成功移入 `done/` 后必须 commit 且不得 push，再开始下一件。

## 状态转换

| 时机                         | Status    | 目录       | 执行者   |
| ---------------------------- | --------- | ---------- | -------- |
| 创建任务                     | `TODO`    | `todo/`    | 创建命令 |
| 开始执行                     | `DOING`   | `doing/`   | 本技能   |
| 未填写 / 无法处理 / 执行阻塞 | `BLOCKED` | `blocked/` | 本技能   |
| 执行完成                     | `DONE`    | `done/`    | 本技能   |
| 需要人规划或澄清             | `PLAN`    | `plan/`    | **仅人** |

本技能不得写入 `PLAN`，不得把文件移入 `plan/`。

## 路由

| 情况                                           | 去向                                                          | 本轮是否继续其他任务         |
| ---------------------------------------------- | ------------------------------------------------------------- | ---------------------------- |
| `blocked/` 中已有 P0                           | 不领取新任务                                                  | 否                           |
| `doing/` 中已有任务                            | 不领取新 TODO                                                 | 否                           |
| 任务 Status 不是 TODO                          | 不执行                                                        | 是（改选其他 TODO）          |
| 任务未填写（`name`/`description` 占位）        | `blocked/`，保留原文件名                                      | 非 P0 继续；P0 停止          |
| 文档填写不符合要求                             | `blocked/` + `BLOCKED`，保留原文件名                          | 非 P0 继续；P0 停止          |
| Agent 无法处理（需人拍板、缺 ADR、需求冲突等） | `blocked/` + `BLOCKED`，保留原文件名                          | 非 P0 继续；P0 停止          |
| 外部环境、密钥、第三方账号不具备               | `blocked/` + `BLOCKED`，保留原文件名                          | 非 P0 继续；P0 停止          |
| 执行过程中阻塞                                 | `blocked/` + `BLOCKED`，保留原文件名                          | 非 P0 继续；P0 停止          |
| 依赖的 TASK 仍未完成                           | 留在 `todo/`，本轮跳过                                        | 是                           |
| 成功实现                                       | `done/` 根下 + `DONE`（禁止年份子目录），随后 commit、不 push | 是，commit 后再做下一件      |
| 实现中验证失败、缺护栏、无法安全改代码         | 停这一条；能回退则回退                                        | 能回退则继续；不能回退则停止 |
| 用户要求停止                                   | 全部停止                                                      | 否                           |

## 文件名

- 各目录均保留原文件名，例如 `task-YYYYMMDDHHmmSS.md` 或 `TASK-<编号>-<短名>.md`。
- 不要为进入 `blocked/` / `doing/` / `done/` 而改名。
- 完成任务直接放在 `done/` 根下，禁止 `done/<年份>/`。
- 不要把文件改名为 `TASK-xxx-plan.md`。
- frontmatter 中 `name` 保持不变，便于人认出来。

## Agent 无法处理（进 blocked/，不要猜）

下列任一即视为本技能处理不了，移入 `blocked/` 并改为 `BLOCKED`，即使任务看起来写得很完整：

- 新增或改动 ADR 所覆盖的分层、进程边界、协议（如 AG-UI / HTTP / IPC），且现有 ADR 未允许
- 改表结构、实体关系、持久化字段语义、迁移策略
- 改公共 API 的路径、方法、请求/响应、错误码、鉴权
- 改主路径：登录、会话、消息投递、Agent 循环、部署/启动顺序等，且方向未定
- 产品行为有多种合理解释，任务未选定
- 需要新的 ADR，或必须确认架构方向
- 需求互相冲突，或与已有 ADR 冲突
- 范围过大、边界不清，无法安全实现
- 与 `todo/` / `doing/` / `blocked/` 中其他任务在目标、模型、API 或流程上互相否定

内部函数拆分、文件搬家、局部实现细节不算「无法处理」，由执行 Agent 自己决定。

只是「要等 TASK-XXX 先做」→ 本轮跳过，不要进入 `blocked/`。

## 不要当成 blocked/ 的情况

- 技术步骤未拆分：执行 Agent 自己决定内部步骤。
- 文件怎么命名、函数怎么拆：自行决定。
- 测试怎么写：自行决定，除非验收所需行为本身缺失（那种算无法处理）。
- 依赖任务还没做完：跳过，不要移入 `blocked/`。

## plan/ 仅人工

- 本技能不扫描、不执行、不改写 `plan/`。
- 用户点名 `plan/` 中的任务时：拒绝执行，因其 Status 不是 TODO。
- 人把任务改回 TODO 并移到 `todo/` 之后，本技能才可以领取。
